# 阶段 2：方案初设

## 阶段状态

- 状态：已确认
- 目标：确定系统边界、组件职责、高层状态图、动态路径和验收策略
- 实际用时：约 6 分钟

## 用户与目标

目标用户是需要快速生成短视频脚本的内容创作者。系统需要生成有素材依据、符合目标时长、可继续编辑的脚本，并公开素材来源、检查结果、风险与任务状态。

## 输入边界

用户请求包含：

- 主题
- 受众
- 平台
- 目标时长
- 风格
- 可选的产品或素材范围

仓库数据包含：

- 产品素材及事实
- 品牌规则

## 输出边界

最终结果包含：

- 标题
- 分镜
- 每个分镜的旁白或字幕
- 每个分镜的预计时长
- 预计总时长
- 每个分镜对应的素材来源 ID
- 风险说明
- 任务状态和终止原因

项目不包含界面、线上部署、多 Agent、生产级持久化或外部知识库。

## 总体调用流程

```text
CLI 输入
  → 输入规范化
  → LangGraph 模型决策节点
      → 素材检索工具 ─┐
      → 时长估算工具 ─┼→ 结构化观察 → 模型再次决策
      → 规则检查工具 ─┘
      → 请求补充 / 失败 / 提交完成
  → 完成守卫
  → JSON 结果与 Trace
```

核心循环是：

```text
模型选择动作 → 执行工具 → 观察结果 → 模型调整下一步或结束
```

## 组件职责

- LangGraph：状态管理、节点编排、循环、路由和终止。
- 模型节点：选择检索、估时、规则检查、请求补充、失败或完成，并可在动作中提交脚本修订版。
- 素材检索工具：检索已有事实并返回素材 ID，不生成新事实。
- 时长估算工具：估算各分镜和总时长。
- 规则检查工具：检查来源引用、无依据数字、品牌禁用表达和结构要求。
- 完成守卫：阻止未通过最新时长检查和规则检查的脚本完成。
- Trace 记录器：记录公开动作依据、参数、结果摘要和下一动作。
- 模型适配器：统一真实模型与 Scripted Mock 的调用契约。

## 高层任务状态

- `running`：正在决策或调用工具。
- `completed`：最新脚本通过完成守卫。
- `needs_input`：缺少关键输入或必要素材。
- `incomplete`：达到模型步数或工具调用上限。
- `failed`：工具持续失败或当前约束明确无法满足。

## 主要动态路径

### 正常生成并修正时长

```text
检索素材 P01
→ 生成首稿并估算为 38 秒
→ 模型观察超时
→ 压缩脚本并再次估时
→ 估算为 28 秒
→ 规则检查通过
→ 完成
```

### 检索无结果

```text
首次检索为空
→ 模型改写查询
→ 再次检索
→ 仍为空时，请求用户补充或明确失败
```

### 规则不通过

```text
检查发现“效率提升 80%”无素材依据
→ 模型删除或改写该结论
→ 再次检查
→ 通过后完成，或说明无法满足
```

### 工具失败

```text
工具返回结构化错误观察
→ 模型结合剩余预算决定重试或终止
→ 持续失败时返回 failed 或 incomplete
```

### 缺少关键信息

```text
输入规范化提供缺失字段观察
→ 模型不生成臆测脚本
→ 返回 needs_input 和需补充字段
```

## 事实约束初设

1. 素材工具只返回数据文件中存在的事实和素材 ID。
2. 每个分镜声明素材来源；纯创意或转场镜头可以没有产品事实和来源。
3. 产品事实进一步绑定事实 ID，使规则工具能核对事实是否属于所引用素材。
4. 无来源定量结论和品牌禁用表达会阻止完成。
5. 检查工具无法证明的开放世界结论必须作为风险披露，不得当作已验证事实输出。

## 验收规划

计划提供五组实际运行记录：

1. 正常生成，并完成 38 秒到 28 秒的修正。
2. 缺少关键信息并请求补充。
3. 检索无素材，改写查询后仍无结果。
4. 工具异常，模型决定重试或终止。
5. 规则检查发现无依据事实并触发修正。

测试层次：

- 工具单元测试
- LangGraph 状态转换测试
- 离线端到端测试
- 真实模型集成测试
- 步数和工具调用上限测试

## 已知风险

- 模型动作结构可能无效，需要校验并形成可观察错误。
- 模型可能过早完成，需要完成守卫。
- 检查报告可能针对旧脚本，需要脚本修订号或指纹关联。
- 工具错误不能和业务空结果混为一谈。
- Mock 记录不能被表述为真实模型决策效果。
