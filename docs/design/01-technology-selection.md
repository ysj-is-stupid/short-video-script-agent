## 为什么选择 LangGraph

1. 本题是显式的有状态循环：模型需要持续观察检索、时长和规则检查结果，再选择下一动作。
2. `StateGraph` 能把“模型决策 → 工具执行 → 观察 → 再决策”表示为可审查的图，而不是只留下文本日志。
3. 状态中可以集中维护素材、脚本修订版、检查报告、调用计数和终止原因，便于测试不同路径。
4. 条件边只路由模型已经选择的动作，不使用固定业务分支冒充模型决策。
5. LangGraph 的递归限制可作为最后保险；项目仍会实现显式模型步数和工具调用预算，以便超限时返回业务可读的 `incomplete`。
6. 节点输入输出天然适合生成结构化 Trace，并能对状态转换做确定性测试。

## 框架使用边界

- LangGraph：状态、节点、循环、路由、执行边界。
- 模型：选择动作、生成或修订脚本、改写查询、决定请求补充或结束。
- 工具：返回可观察事实，不替模型决定下一步。
- 完成守卫：只验证完成前置条件，不生成业务内容。
- Scripted Mock：验证流程、错误处理和状态转换，不作为真实模型决策效果证据。

核心实现不使用一键式预构建 ReAct Agent。采用显式 `StateGraph`，以便准确控制素材引用、分镜时长、检查报告、调用上限和终止状态。

## 取舍

### CLI 而非 HTTP API 或 Notebook

- CLI 最容易提供可复制命令和 JSON 输入输出。
- 不需要为服务生命周期、端口和 Notebook 状态投入额外时间。
- 测试可直接调用相同的应用入口和图构建函数。

### OpenAI SDK 而非绑定 LangChain 模型类

- 通过自有 `ModelAdapter` 隔离供应商协议，LangGraph 不依赖某个特定聊天模型实现。
- 离线 Mock 与真实模型使用同一个 `AgentDecision` 返回类型。
- 后续更换模型只影响适配器，不影响图、工具和测试。

### 本地工具而非外部业务服务

- 题目允许本地函数或 Mock。
- 本地合成素材可以稳定复现无结果、工具失败和规则违规。
- 规则与事实边界可随仓库一起接受评审。

## 主要风险

- 真实模型的输出存在非确定性，需要结构化输出校验和清晰失败状态。
- 时长只能估算，不能替代真人试读。
- 本地规则检查只能覆盖仓库中明示的素材和规则，不能完成开放世界事实核验。
- 若评审环境没有模型密钥，只能复现 Mock 流程；文档必须清楚标明该边界。
