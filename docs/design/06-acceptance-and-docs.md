# 阶段 6：补齐验收场景与文档

## 阶段状态

- 状态：已完成；后续第二轮审计已扩充验证材料
- 目标：用仓库内合成资料实际执行全部必验路径，并完成规定的交付文档
- 实际用时：约 45 分钟

## 场景设计

### 01 正常生成与时长修正

- P01 只提供“支持字幕”事实。
- 目标时长 30 秒。
- Mock 首稿设计为约 38 秒，观察超时后提交压缩修订稿，目标为 28 秒。
- 最终必须包含分镜、P01 来源、通过的时长报告和规则报告。

### 02 缺少关键信息

- 输入缺少 `audience`。
- 期望模型选择 `request_input`。
- 不应调用任何业务工具或生成脚本。

### 03 无素材

- 请求将素材范围限定为不存在的 P99。
- 首次检索为空后必须使用不同查询再次检索。
- 仍无结果时返回 `needs_input/no_supporting_materials`，不得生成产品事实。

### 04 工具失败

- 通过 CLI 故障注入令素材检索连续两次返回可重试错误。
- 第一次错误后模型选择重试；第二次错误后选择 `fail`。
- 错误不能被记录为空检索结果。

### 05 无依据事实修正

- 首稿故意加入“效率提升80%”。
- P01 没有任何效果数据。
- 规则检查必须拒绝；模型删除该结论后重新完成时长和规则检查。

## 正式数据

- `data/materials.json`：合成产品素材。
- `data/brand_rules.json`：合成品牌规则。
- 不包含真实品牌、个人信息或业务密钥。

## 运行记录格式

每个场景目录包含：

- `input.json`
- `output.json`
- `trace.json`

Trace 中的 `review_steps` 直接提供：

- 工具参数
- 返回种类与摘要
- 实际发生的后续动作
- 简短公开决策依据
- 对应脚本修订号

- `docs/01-requirements.md`：用户、目标、范围和成功标准。
- `docs/02-solution.md`：LangGraph 流程、动态决策和取舍。
