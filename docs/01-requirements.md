# 01 需求与成功标准

## 用户

目标用户是需要快速生成短视频脚本的内容创作者和品牌内容运营人员。

## 目标

Agent 根据用户约束和仓库内产品素材，生成可编辑、满足目标时长且事实可追溯的短视频脚本。它必须在工具结果变化时调整下一动作，而不是只执行固定分支。

## 输入

- 主题、受众、平台、目标时长和风格。
- 可选的产品名、素材范围和品牌规则范围。
- 产品素材与品牌规则由本地 JSON 提供。

## 输出

- 标题。
- 分镜、画面、旁白或字幕。
- 每个分镜和总预计时长。
- 素材来源 ID 与内部事实 ID。
- 时长检查、规则检查、风险与任务状态。
- 可审查的结构化 Trace。

## 范围

本项目包含 CLI、LangGraph ReAct 循环、真实模型适配器、离线 Mock、三项本地工具、测试、合成数据、核心验收及扩展失败/预算示例和文档。

本项目不包含界面、线上部署、多 Agent、外部知识库和生产级 Runtime。

## 动态决策要求

```text
模型选择动作 → 执行工具 → 观察结果 → 模型调整下一动作或结束
```

必须能观察到检索为空后改写或请求补充、时长超限后修改并重估、规则不通过后修改并重查、工具失败后重试或结束，以及超限时明确未完成。

## 必验场景

1. 正常生成。
2. 缺少关键信息。
3. 无素材。
4. 工具失败。
5. 超时长后的修正或明确失败。

额外加入“无依据事实修正”，验证 P01 不包含效果数据时不能保留“效率提升80%”。

## 成功标准

- 项目可以用 README 中的命令运行。
- 正常输出包含标题、分镜、旁白或字幕、总时长、素材 ID、风险和状态。
- 素材 ID、事实 ID、分镜和检查报告能对应。
- 至少两条 Trace 展示不同工具结果引发不同后续动作。
- 最新脚本必须通过对应版本的时长与规则检查才能完成。
- 无结果、工具错误和规则拒绝不能混为同一种观察。
- 超限返回 `incomplete`，不以无限循环或框架异常结束。
- 测试可以离线执行，Mock 边界明确。
